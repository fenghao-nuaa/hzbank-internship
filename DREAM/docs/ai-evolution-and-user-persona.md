# AI 决策进化与用户画像

## 解决的问题

普通 Agent 的一次会话结束后，用户偏好和处理经验通常只留在聊天记录里。下一次任务开始时，Agent 不知道用户已经表达过什么，也无法复用过去验证有效的判断方法。

DREAM 将完成的会话转化为两类长期知识：

- **用户画像**：描述用户稳定的偏好、习惯、约束和长期目标；
- **AI 决策经验**：描述 Agent 在相似任务中应该如何判断、何时停止以及满足什么条件才能继续。

这两类知识相互隔离。用户画像属于具体用户，不能跨用户使用；AI 决策经验属于具体 Agent，可以服务同一 Agent 下的不同用户。

## 从会话到长期知识

一次完整链路如下：

```text
完成的 Conversation
        ↓
写入 Event Ledger
        ↓
Agnes 发现长期知识
        ↓
Provider Adapter 统一外部模型格式
        ↓
Knowledge Governance 分类与校验
        ↓
用户画像 / AI 决策经验 / Skill 候选
        ↓
快照、版本、写回与激活
```

Agnes 只负责从会话中发现候选知识。DREAM 的本地代码负责：

1. 将不同模型的 JSON、工具调用和包装字段转换成统一结构；
2. 判断候选属于用户画像、决策规则还是工作流 Skill；
3. 校验来源事件、置信度和必要字段；
4. 合并已有知识并处理重复或冲突；
5. 根据风险等级决定自动激活、继续观察或等待审核；
6. 创建可追溯的快照、版本和运行报告。

因此，外部模型不会直接修改 DREAM 的长期文件。

## 用户画像

### 两份画像文件

用户画像保存在用户作用域内：

```text
users/<user_id>/
├── USER.md
└── USER_PERSONA.md
```

- `USER.md` 是长期画像仓库，保存原子画像、来源事件、置信度、领域和合并信息；
- `USER_PERSONA.md` 是面向 Agent 的画像投影，提供更紧凑、适合任务上下文的用户描述。

`USER.md` 负责完整保存，`USER_PERSONA.md` 负责便于使用。存储容量与模型上下文预算相互分离，长期画像不会因为单次上下文长度限制而停止增长。

### 画像如何持续演化

DREAM 不把整份 `USER.md` 当作一个字符串反复重写，而是把画像拆成原子条目。Persona Canonicalizer 和 Persona Merge Strategy 会把新证据分成四种情况：

| 类型 | 含义 | 处理方式 |
|---|---|---|
| `new` | 新领域或独立的新特征 | 新增原子画像 |
| `update` | 新证据修正已有画像 | 更新目标画像 |
| `merge` | 为已有画像增加新维度 | 无损合并后替换 |
| `duplicate` | 没有新增信息 | 不重复写入 |

画像合并不仅比较一句概括，还会保留候选中的信号、步骤、约束和新增信息。例如，已有画像是“用户重视风险控制”，新会话又表明用户要求区分事实、推断和未知，DREAM 应把这些新维度合并进去，而不是把候选当作重复内容丢弃。

画像还包含领域信息。银行操作偏好、加密资产投资偏好、写作习惯和编程习惯即使出现相似词，也不会仅凭关键词被错误合并为同一条画像。

## AI 决策经验

### Decision Card

具有长期价值的判断经验会形成 Decision Card。每张卡片包含：

- 使用场景；
- 决策信号；
- 决策原则；
- 预期结果；
- 反例与适用边界；
- 置信度；
- 来源事件。

Decision Card 位于 Agent 作用域的 `decision-cards/` 目录。相同主题出现新证据时，DREAM 可以更新既有卡片并合并来源，而不是不断创建语义重复的文件。

### DECISION_RULES.md

确定性 AI Curator 从当前有效的 Decision Cards 中提炼稳定规则，生成：

```text
DECISION_RULES.md
```

这份文件是面向 Agent 的决策规则投影。Decision Cards 保留完整证据，`DECISION_RULES.md` 提供下一任务可直接使用的简明原则。

这种分层方式使 AI 的“进化”不是修改模型参数，而是让 Agent 持续积累可检查、可更新、可回滚的判断经验。

## 自动治理与生效

每个候选知识都会进入治理策略：

```text
低风险且证据充分       → 自动写回并激活
信息不足或需要重复确认 → 保存为观察候选
敏感、权限或高风险内容 → 等待人工审核
```

普通且稳定的表达偏好、工作习惯和结构完整的决策经验可以自动生效。身份信息、权限放宽、绕过验证或高风险金融操作不会在缺少审核时直接进入 Active Memory。

写回之前 DREAM 创建 before snapshot；写回成功后创建 after snapshot 和 Publication Version。任何本地步骤失败时都会恢复原快照，保留未完成事件，避免产生半写入状态。

## 下一任务如何使用

下一任务可以通过两种方式读取已经激活的知识：

1. `/v1/tasks/start` 创建一致性快照，并返回用户画像、决策规则和相关决策卡；
2. 外部 Agent 调用 `MemoryRetrievalSkill`，根据当前问题检索少量相关记忆。

检索过程会执行用户隔离、类型过滤、领域判断、相关性排序、去重和上下文预算控制，避免每次把全部长期记忆塞入模型。

因此，DREAM 的完整循环是：

```text
新会话
  ↓
形成或更新长期知识
  ↓
激活新版本
  ↓
下一任务检索相关画像和决策经验
  ↓
Agent 使用新知识完成任务
```

## 当前能力边界

- DREAM 形成的是外部、可审计的长期知识，不训练或微调基础模型；
- User Persona 和 Decision Card 已支持本地写回、版本、快照和自动治理；
- Workflow Skill 可以被识别并记录为 `pending_skill_implementation`；
- Skill 候选目前不是可执行的 Skill Runtime，不会被当作已经验证的自动化能力调用；
- Memory Retrieval 当前使用本地确定性检索，不依赖向量数据库；
- 高风险知识仍然保留人工审核能力。
