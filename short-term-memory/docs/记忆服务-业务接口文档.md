# 短期记忆服务 · 业务接口文档

> 本服务为 Agent 应用提供短期记忆能力：自动存储对话与文件上下文，通过 Claude 风格 L1–L4 上下文管理与 Headroom generation 压缩控制当前上下文，需要精确细节时按需召回原文。模型调用由 Agent 侧独立完成。

## 一、接入总览

### 主要业务接口

| 接口 | 方法 | 作用 |
|---|---|---|
| `/v1/memories/activate` | POST | 写入前激活 session；Redis 过期时从 Journal 恢复有界上下文 |
| `/v1/memories/write` | POST | 存入对话/文件内容到记忆 |
| `/v1/memories/read` | POST | 取回当前会话的上下文（压缩摘要 + 最近原文） |
| `/v1/memories/prepare` | POST | 组装 Agent 请求上下文，并执行请求时 L1→L2→L4→L3 |
| `/v1/memories/recall` | POST | 按标记取回被压缩的原文（模型信息不足时使用） |
| `/v1/memories/transcript/grep` | POST | 在当前 session Journal transcript 中定位原文 |
| `/v1/memories/transcript/read` | POST | 按 sequence 范围读取 Journal 精确原文 |

### Agent 调用记忆服务的完整流程

```
Agent 收到用户消息
  ①  activate ──── 在新写入前恢复历史 session 的有界上下文和 sequence
  ②  write ──────── 存入用户消息/附件
  ③  prepare ────── 取回 L3/L4 summary + Headroom generation + 最近原文
  ④  调用模型 ──── 使用 prepare 返回的 messages、tools 和 Headroom 代理信息
  ⑤  判断 tool_calls
  ⑥  recall 或 Grep→Read ── 按需召回 CCR 或 Journal 精确原文
  ⑦  write ──────── 存入模型回答
```

### 存储与压缩说明

- **原文存储**：对话与文件内容写入 Redis（在线热数据，默认 12 小时）与 Journal（持久日志，默认 30 天）。
- **压缩时机**：上下文 token 超过模型窗口的 60%–70%，或消息数/会话时长超过阈值时，服务后台自动调用 Headroom 压缩。
- **压缩结果**：L3 `active_revision` 与 L4 `session_memory` 存入 Redis，并立即以不可变 `compaction_checkpoint` 写穿 Journal；Headroom generation 与 CCR marker/hash 继续由 Headroom 管理。
- **上下文瘦身**：压缩后，已压缩的原文从 Redis 在线存储移除，模型后续只看到压缩摘要 + 最近未压缩消息，需要细节时通过召回取回原文。

## 二、激活历史会话 POST /v1/memories/activate

在向任何 session 写入新消息前调用。Redis 仍存活时该接口是幂等快速路径；Redis 已过期时，服务从 Journal 恢复最新 L3/L4 checkpoint、最近 N 个完整用户轮次与历史最大 sequence。恢复后的下一条新消息从 `latest_sequence + 1` 开始。

恢复后同时后台投递 `rebuild=true` 的 Headroom cold rebuild，重建新 generation/marker/CCR；同步路径不等待 Headroom 或新的摘要模型请求。

### 请求体

```json
{
  "user_id": "u-001",
  "session_id": "s-old",
  "history_turns": 10
}
```

### 响应体

```json
{
  "request_id": "req-xxx",
  "recovered": true,
  "latest_sequence": 180,
  "checkpoint_id": "sha256:...",
  "rebuild_queued": true
}
```

`checkpoint_id` 只用于恢复状态和运维诊断。接口不返回 checkpoint 内容、CCR 原文或用户可见的历史预览。需要精确代码、错误、工具结果或原始措辞时，Agent 先使用当前 session scope 下的 CCR marker；CCR 不可用时按 `Grep → Read → Journal 原文` 召回。

## 三、写记忆 POST /v1/memories/write

将一条或多条对话/文件内容存入记忆。

### 请求体

```json
{
  "user_id": "u-001",
  "session_id": "s-001",
  "events": [
    {
      "event_id": "client-生成的唯一id",
      "role": "user",
      "content_type": "conversation",
      "content": "用户说的内容",
      "metadata": {}
    }
  ],
  "session_seconds": 120
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | string | 用户标识，用于隔离不同用户 |
| `session_id` | string | 会话标识，同一会话共享记忆 |
| `events` | array | 待写入的事件列表，支持批量 |
| `events[].event_id` | string | 客户端生成的唯一 ID，用于幂等去重 |
| `events[].role` | string | `user` / `assistant` / `system` / `tool` |
| `events[].content_type` | string | `conversation` / `code` / `document` / `skill` |
| `events[].content` | string | 内容正文 |
| `events[].metadata` | object | 附加元数据 |
| `session_seconds` | int | 会话已持续秒数，参与压缩触发判断 |

### 响应体

```json
{
  "request_id": "req-xxx",
  "accepted": true,
  "sequence_from": 1,
  "sequence_through": 1,
  "duplicate_event_ids": [],
  "compression_queued": false,
  "policy_version": "v1",
  "timing_ms": {
    "total": 20.0,
    "redis": 8.0,
    "journal": 28.0,
    "queue": 1.0
  }
}
```

### 说明

- **幂等**：相同 `event_id` 重试不会重复写入。
- **`compression_queued`**：为 `true` 表示本次写入触发了后台压缩任务（上下文已超阈值）。
- **原文保障**：写入先落 Journal 再提交 Redis，Redis 丢失可从 Journal 恢复。

## 四、读记忆 POST /v1/memories/read

取回当前会话的上下文，供 Agent 组装后发给模型。

### 请求体

```json
{
  "user_id": "u-001",
  "session_id": "s-001",
  "history_turns": 10,
  "include_effective_config": true
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | string | 用户标识 |
| `session_id` | string | 会话标识 |
| `history_turns` | int | 返回最近多少轮原始消息（默认取配置值） |
| `include_effective_config` | bool | 是否返回非敏感配置信息 |

### 响应体

```json
{
  "request_id": "req-xxx",
  "messages": [
    {
      "role": "system",
      "content": "{\"current_goal\":[],\"preferences\":[],\"confirmed_facts\":[],\"pending_items\":[],\"attachment_references\":[]}"
    },
    {
      "role": "assistant",
      "content": "[500 items compressed to 20. Retrieve more: hash=8abe70137f195e528d32a9d8]"
    },
    {
      "role": "user",
      "content": "最近的原始消息"
    }
  ],
  "memory": {
    "compressed_through_sequence": 100,
    "latest_sequence": 101,
    "source": "redis",
    "compression_segments": 1
  },
  "headroom": {
    "proxy_url": "http://127.0.0.1:8787/v1",
    "scope_headers": {
      "x-headroom-user-id": "dream-v1-...",
      "x-headroom-session-id": "dream-v1-...",
      "x-headroom-project-id": "dream-v1-..."
    }
  },
  "ccr_markers": ["8abe70137f195e528d32a9d8"],
  "effective_config": {
    "history_turns": 10,
    "redis_ttl_seconds": 43200,
    "ccr_ttl_seconds": 43200,
    "journal_retention_days": 30,
    "trigger_ratio": 0.65,
    "policy_version": "v1"
  },
  "timing_ms": {
    "total": 31.5,
    "redis": 12.2,
    "recovery": 0.0,
    "assembly": 3.1
  }
}
```

### 关键字段说明

| 字段 | 说明 |
|---|---|
| `messages` | **可直接发给模型**的上下文数组，包含：语义摘要（system）、压缩历史（含 marker）、最近原始消息 |
| `headroom.proxy_url` | 模型调用时要使用的代理地址（Headroom Proxy） |
| `headroom.scope_headers` | 模型调用时要携带的去标识化请求头 |
| `ccr_markers` | 压缩内容的召回标记列表，模型需要历史细节时用这些标记取回原文 |
| `memory.compressed_through_sequence` | 已压缩到的消息序号 |
| `memory.compression_segments` | 有效压缩段数量 |

### 压缩上下文中的 marker

压缩后的历史内容以 marker 形式保留在 `messages` 中，形如：

```
[500 items compressed to 20. Retrieve more: hash=8abe70137f195e528d32a9d8]
```

- marker 告诉模型"这段内容被压缩了，如需细节可召回"
- marker 中的 `hash` 是取回原文的钥匙，同时汇总在 `ccr_markers` 字段

## 五、召回原文 POST /v1/memories/recall

按标记从 Headroom 的 CCR 存储取回被压缩的原文。**当模型判断压缩内容不足以回答时，通过本接口取回原始内容，帮助模型作答。**

### 请求体

```json
{
  "user_id": "u-001",
  "session_id": "s-001",
  "hashes": ["8abe70137f195e528d32a9d8"]
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_id` | string | 用户标识 |
| `session_id` | string | 会话标识 |
| `hashes` | array | 待召回的标记 hash 列表，来自 read 返回的 `ccr_markers` |

### 响应体

```json
{
  "request_id": "req-xxx",
  "results": [
    {
      "hash": "8abe70137f195e528d32a9d8",
      "content": "被压缩的完整原文...",
      "recovered": true
    }
  ]
}
```

### 字段说明

| 字段 | 说明 |
|---|---|
| `results[].hash` | 对应的标记 hash |
| `results[].content` | 取回的完整原文 |
| `results[].recovered` | 是否成功取回（`true` 成功；`false` 表示未找到，可能已过期） |

### 召回触发机制（重要）

**召回接口不是每次都调用，而是在模型需要历史细节时按需触发。** 具体机制如下：

```
① Agent 调 prepare 拿到上下文 messages + tools
② Agent 把 messages 发给模型（经过 Headroom Proxy）
③ 模型判断压缩内容是否足以回答：
   ├─ 足够 → 直接回答（不需要召回）
   └─ 不足 → 模型返回 tool_calls，请求调用 headroom_retrieve(hash=...)
④ Agent 识别到 headroom_retrieve 工具调用
   → 从 tool_calls 中取出 hash
   → 调 /v1/memories/recall 传该 hash
   → 取回完整原文
   → 将原文作为 tool 结果追加进消息
   → 重新发给模型
⑤ 模型基于原文给出准确回答
```

如 CCR 返回 `recovered=false`，Agent 继续使用 prepare 提供的 `Grep` 和 `Read` 工具，从同一历史 session 的 `journal://current-session` 召回原文。

**触发条件示例：**
- 用户询问很久以前、已被压缩掉的细节（如"我之前发的那个文档里，关于 X 是怎么写的"）
- 压缩摘要信息不足以支撑模型作答

**设计说明：**
本服务的召回由 Agent（调用方）主动驱动，而非依赖代理透明续跑。这样召回行为可控、可测试、可运维。Agent 需要实现"识别 headroom_retrieve → 调 recall → 重新请求"这一循环（参考下文接入示例）。

## 六、Agent 接入示例

以下为 Agent 接入的核心代码逻辑（Python）：

```python
import os
import json
import httpx
from openai import OpenAI

MEMORY_URL = "http://127.0.0.1:8080"
USER_ID = "u-001"
SESSION_ID = "s-001"
DEEPSEEK_API_KEY = os.environ["DEEPSEEK_API_KEY"]

def post(path: str, payload: dict) -> dict:
    resp = httpx.post(f"{MEMORY_URL}{path}", json=payload, timeout=30)
    resp.raise_for_status()
    return resp.json()

# ① 激活 session：必须在任何新写入之前
post("/v1/memories/activate", {
    "user_id": USER_ID,
    "session_id": SESSION_ID,
    "history_turns": 10,
})

# ② 写记忆：存入用户消息
post("/v1/memories/write", {
    "user_id": USER_ID,
    "session_id": SESSION_ID,
    "events": [{
        "event_id": "msg-001",
        "role": "user",
        "content_type": "conversation",
        "content": "用户的问题",
        "metadata": {},
    }],
})

# ③ prepare：取回当前模型请求上下文
memory = post("/v1/memories/prepare", {
    "user_id": USER_ID,
    "session_id": SESSION_ID,
    "model_profile": {
        "context_window_tokens": 128000,
        "max_output_tokens": 8192,
    },
})
messages = memory["messages"]
proxy_url = memory["headroom"]["proxy_url"]
scope_headers = memory["headroom"]["scope_headers"]

# ④ 调模型（经过 Headroom Proxy）
client = OpenAI(
    api_key=DEEPSEEK_API_KEY,
    base_url=proxy_url,
    default_headers=scope_headers,
)
completion = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=messages,
)

# ⑤ 处理模型可能的工具调用（召回）
message = completion.choices[0].message
if message.tool_calls:
    for tool_call in message.tool_calls:
        if tool_call.function.name == "headroom_retrieve":
            args = json.loads(tool_call.function.arguments)
            hash_value = args["hash"]
            # ⑥ 调召回接口取回原文
            recalled = post("/v1/memories/recall", {
                "user_id": USER_ID,
                "session_id": SESSION_ID,
                "hashes": [hash_value],
            })
            original = recalled["results"][0]["content"]
            # 将原文追加为 tool 结果，重新请求模型
            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": original,
            })
            completion = client.chat.completions.create(
                model="deepseek-v4-flash",
                messages=messages,
            )
            message = completion.choices[0].message

answer = message.content

# ⑦ 写记忆：存入模型回答
post("/v1/memories/write", {
    "user_id": USER_ID,
    "session_id": SESSION_ID,
    "events": [{
        "event_id": "msg-002",
        "role": "assistant",
        "content_type": "conversation",
        "content": answer,
        "metadata": {},
    }],
})
```

## 七、认证与部署

### 认证

所有业务接口需要携带 Bearer Token：

```
Authorization: Bearer <MEMORY_API_AUTH_TOKEN>
```

`MEMORY_API_AUTH_TOKEN` 通过环境变量配置，生产环境必填。

### 服务启动

```bash
# 启动记忆服务 API
uv run short-term-memory-api

# 启动压缩 worker（后台异步压缩）
uv run short-term-memory-worker

# 依赖的外部服务
# - Redis（在线存储）
# - Headroom（压缩与 CCR 原文存储）
```

### 配置项

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `REDIS_URL` | `redis://127.0.0.1:6379/0` | Redis 连接 |
| `REDIS_SESSION_TTL_SECONDS` | `43200` | Redis 记忆有效期（12 小时） |
| `JOURNAL_RETENTION_DAYS` | `30` | Journal 原文保留天数 |
| `HEADROOM_SERVICE_URL` | 必填 | Headroom 服务地址 |
| `HEADROOM_CCR_TTL_SECONDS` | `43200` | CCR 召回上下文有效期 |
| `HEADROOM_TRIGGER_RATIO` | `0.65` | 压缩触发比例（0.60–0.70） |
| `HEADROOM_MAX_MESSAGES` | `100` | 消息数压缩阈值 |
| `HEADROOM_MAX_SESSION_SECONDS` | `14400` | 会话时长压缩阈值 |
| `MEMORY_API_AUTH_TOKEN` | 空 | API 认证令牌（生产必填） |
| `DEEPSEEK_API_KEY` | — | DeepSeek 密钥，由 Agent 侧持有 |
